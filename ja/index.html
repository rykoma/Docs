Microsoft Graph とメールのいろいろな添付

Microsoft Graph でメールの添付を取得する方法は、List attachments や Get attachments に記載されています。List messages などでメールを取得する際に /messages?$expand=attachments のようにリクエストして、まとめて取得する方法もあります。

ですが、その前に Exchange Online のメールの添付にはいくつかの種類があることを理解する必要があります。

ファイルの添付

Excel ファイルが添付されているなど、いわゆる通常の添付ファイルです。Microsoft Graph では fileAttachment リソースとして表現されます。

/messages でメールを取得したとき、ファイルの添付がある場合は hasAttachments が true になっています。

Outlook アイテムの添付

メールや予定などの Outlook アイテムが添付されている場合は、通常の添付ファイルとは扱いが異なり、Microsoft Graph では itemAttachment リソースとして表現されます。

/messages でメールを取得したとき、Outlook アイテムの添付がある場合も hasAttachments は true になっています。

eml ファイルが添付されている場合は fileAttachment になりますが、msg ファイルが添付されている場合は itemAttachment になります。

インライン添付

本文に埋め込まれた画像です。署名に画像が含まれている場合もインライン添付です。Microsoft Graph では fileAttachment リソースとして表現されます。

/messages でメールを取得したとき、インライン添付があっても hasAttachments は false になっています。本文に埋め込まれているためメールの body を取得すると img タグがあり、src 属性には cid:f81e14a3-1bfe-491e-a2bb-e53481d97473 のような文字列が設定されています。

fileAttachment リソースなので /attachments などで取得が可能で、取得すると isInline が true になっています。また、contentId には img タグの src 属性に設定されていた cid の値が設定されており、本文内の位置と対応させることができます。

クラウド添付

OneDrive などのリンク情報を添付としたものです。現在の Outlook ではこの種類のリンクを新たに作成する操作はありません。Microsoft Graph では referenceAttachment リソースとして表現されます。

Remote PowerShell コマンドの既定の出力内容

Note

この記事は、2018 年当時の技術的な記録です。ここで使用する New-PSSession による Exchange Online Remote PowerShell 接続は、Microsoft による Remote PowerShell の廃止に伴い、現在は使用できません。手順とコード例は当時の内容を残しています。現在の接続方法については、Microsoft Learn の Exchange Online PowerShell への接続 を参照してください。Remote PowerShell の廃止については、Microsoft の Exchange Online における Remote PowerShell の廃止 を参照してください。

Note

2018 年 8 月 1 日の更新: 2018 年 5 月ごろから順次、Get-Mailbox コマンドの既定の出力は Name、Alias、Database、ProhibitSendQuota、ExternalDirectoryObjectId に変更されています。

Exchange Online の PowerShell に接続して Get-Mailbox コマンドを実行すると、既定で Name、Alias、ServerName、ProhibitSendQuota の 4 つが出力されているはずです。

Get-Mailbox の結果を Format-List (fl) で表示すると分かるように、オブジェクトにはほかにも多くの属性があります。コマンドだけを実行して表示する属性を指定しなかったときに何を出力するかは、PowerShell モジュールに含まれるフォーマット設定で決まります。

どのように設定されているのかを確認するため、まずは通常どおり New-PSSession コマンドで PSSession を作成します。

通常はこの後に Import-PSSession コマンドを実行しますが、今回は PSSession を PowerShell モジュールとしてファイルに書き出します。そのために Export-PSSession コマンドを使用します。

OutputModule には出力先のフォルダー名を指定します。

このコマンドを実行すると、.format.ps1xml、.psd1、.psm1 の 3 つのファイルが出力されます。このうち .format.ps1xml がコマンドの既定の出力内容を定義するファイルです。特殊な拡張子ですが、中身は XML のテキスト ファイルなので、メモ帳などで開けます。

ファイルを開いたら、Microsoft.Exchange.Data.Directory.Management.Mailbox を検索してください。これは Get-Mailbox コマンドなどの結果のデータ型です。既定では Name、Alias、ServerName、ProhibitSendQuota の 4 つが出力対象になっていることが分かります。

試しに ProhibitSendQuota の代わりに AdminDisplayVersion を表示するようにしてみましょう。TableColumnHeader と TableColumnItem に登場する ProhibitSendQuota を、それぞれ AdminDisplayVersion に置き換えて保存します。

置き換えた内容でモジュールをインポートします。先ほど OutputModule に指定したパスを Import-Module コマンドに指定して実行します。

これで Get-Mailbox を実行すると、ProhibitSendQuota の代わりに AdminDisplayVersion が出力されます。

Exchange 管理シェルとリモート PowerShell のデータ型の違い

Note

この記事は、Exchange Server の管理シェルとリモート PowerShell で 2017 年に確認した動作を説明します。Exchange Online の動作を説明するものではありません。

Exchange 管理シェルとリモート PowerShell では、データ型が異なる場合があります。

例えば、トランスポート ルールに承認者が設定されている場合は、ModerateMessageByUser で確認できます。Exchange Server の管理シェルでは、System.Array クラスを継承した RecipientIdParameter 型の配列です。

一方、リモート PowerShell では ArrayList 型です。

この型の違いは、要素数の取得方法に影響します。RecipientIdParameter 型の配列では、Length プロパティと拡張メソッドの Count のどちらでも要素数を取得できます。ArrayList 型で要素数を取得するには、Count プロパティを使用します。

さらに注意が必要なのが、リモート PowerShell の接続元のバージョンです。PowerShell 2.0 では問題ありませんが、3.0 以降では、各要素のプロパティに動的にアクセスして配列を取得できます。

そのため、リモート PowerShell では ArrayList 型に対しても Length で値を取得できます。これは ModerateMessageByUser の各要素のデータ型が String であり、String 型が Length プロパティを持つためです。

つまり、PowerShell 3.0 以降から接続したリモート PowerShell で ModerateMessageByUser.Length にアクセスすると、各要素の文字数を格納した配列が返されます。これは要素数ではありません。

スクリプトを作成する際は、データ型を意識して実装する必要があります。
