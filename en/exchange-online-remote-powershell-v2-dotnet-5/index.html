Connect to Exchange Online with the Remote PowerShell V2 Module in C# (.NET 5.0)

Updated: 2026-11-24

Important

This article records procedures from 2021. Remote PowerShell for Exchange Online has been retired, so this connection method no longer works. Support for .NET 5 ended on May 10, 2022, and it no longer receives security updates or technical support. See the Exchange Team Blog on Remote PowerShell retirement, the Microsoft .NET lifecycle information, and the current Exchange Online PowerShell documentation. The sample below is a historical record; do not embed passwords in code.

For other runtime environments, see:

  • Connect to Exchange Online with the Remote PowerShell V2 Module in C# (.NET Framework 4.7.2)
  • Connect to Exchange Online with the Remote PowerShell V2 Module in C# (.NET Core 3.1)

The following documentation describes how to connect to Exchange with PowerShell from a program:

Get a list of mail users by using the Exchange Management Shell

At the time this article was written, this documentation had not been updated since September 2015. Although it is useful as a reference, it describes a connection to a remote runspace. In simple terms, a remote runspace runs commands on an Exchange server or an Exchange Online server. It is therefore subject to various security restrictions. For example, common scripting syntax such as variables and assignment expressions is not available.

A local runspace, which does not have those restrictions, is needed instead, but no sample code for this approach has been published. The steps are nevertheless the same as when connecting to Exchange Online from Windows PowerShell. With the traditional Basic authentication connection, New-PSSession and Import-PSSession import the Exchange Online commands into the local runspace. When using the Exchange Online PowerShell V2 module, Connect-ExchangeOnline runs New-PSSession and Import-PSSession internally.

This article explains how to connect to Exchange Online from C# using the Exchange Online Remote PowerShell V2 module. It assumes familiarity with Visual Studio and C# application development, so it does not provide detailed step-by-step instructions.

Environment

The sample was tested in the following environment:

  • Visual Studio 2019
  • .NET 5.0
  • PowerShell 7.1.3
  • ExchangeOnlineManagement PowerShell module 2.0.5
  • Microsoft.PowerShell.SDK 7.1.3
  • System.Management.Automation 7.1.3

The runtime environment is .NET 5.0, so the sample uses PowerShell 7, which runs on .NET. Windows PowerShell, which runs on .NET Framework, cannot be used in this environment.

This sample is not intended to run in Azure Functions. Connecting to Exchange Online PowerShell from Azure Functions might work, but it is not strictly supported. The ExchangeOnlineManagement PowerShell module is intended to run on client computers and might not work correctly in Azure Functions.

Prerequisites

Both the development and production environments must already be configured to connect using the ExchangeOnlineManagement PowerShell module. Refer to the documentation to prepare the environment. If the account running the program differs from the user installing the module, install it with the Install-Module command’s Scope parameter set to AllUsers.

To connect using a certificate, first configure certificate-based connections by following, for example, Connect to Exchange Online PowerShell non-interactively.

Steps

  1. Start Visual Studio and create a new C# console application project targeting .NET 5.0.
  2. Install Microsoft.PowerShell.SDK and System.Management.Automation in the project using NuGet. Install the versions listed in Environment.
  3. Use the following code as a reference:
  1. The code implements the following four methods provided by Connect-ExchangeOnline. In V2ModuleExchangeOnlineRemotePowerShell, comment out all but the connection method you want to try:
    • UPN and password (ConnectExchangeOnlineUsingUserPrinsipalNameAndPassword)
    • PFX file (ConnectExchangeOnlineUsingPfxFile)
    • Certificate thumbprint (ConnectExchangeOnlineUsingThumbprint)
    • X509Certificate2 object (ConnectExchangeOnlineUsingX509Certificate2)
  2. Start debugging. If it runs successfully, the results of Get-Mailbox and Get-EXOMailbox are displayed.

Additional explanation

The WriteStreams method writes the executed command’s error, warning, and information streams to the console. Standard output is written separately for each command where needed.

Each of the four connection methods requires environment-specific information. Change the variables, such as the tenant name, to match your environment.

The sample specifies PSSessionOption so that Connect-ExchangeOnline uses the IE proxy settings. This setting is not necessarily required in an environment without a proxy server. When collecting a Fiddler trace for troubleshooting, it allows Exchange Online traffic to go through Fiddler as well.
