このブログを WordPress から GitHub Pages に移行しました。移行先の選定から、サイトの構築、記事の移行、英語版の作成まで、ほぼすべての作業を GitHub Copilot と一緒に進めました。

この記事では、移行を決めた理由と、新しいブログの構成、Copilot との作業で印象に残ったことを紹介します。

## 移行しようと思った理由

以前のブログは、Azure App Service 上の WordPress と Azure Database for MySQL を使って運用していました。しかし、私はこれらのサービスに関する知識がほとんどなく、メンテナンスが大変でした。

また、個人ブログに潤沢なリソースを割り当てるほどの投資はできず、動作が遅いことにもストレスを感じていました。もう少しシンプルで、費用や保守の負担を抑えられる構成にしたいと考え、移行を検討することにしました。

## 移行先に Hexo と GitHub Pages を選んだ

移行先を考えるにあたって、別の WordPress ホスティング サービスやブログ サービスも比較しました。その中で、ランニング コストがかからない GitHub Pages を選びました。

記事を管理する仕組みとして選んだのは、静的サイト ジェネレーターの Hexo です。普段の仕事で Hexo を使っていて、なじみがあったことが決め手でした。

新しいブログでは、記事を Markdown ファイルとして Git で管理し、GitHub Actions でサイトをビルドして GitHub Pages に公開しています。テーマには Landscape を使用し、必要なカスタマイズも行いました。

移行にあたっては、これまでの記事へのリンクをできるだけ維持するため、旧 WordPress の URL から新しい URL へリダイレクトするようにしました。WordPress では日本語の記事しか用意していませんでしたが、移行に合わせて英語版も作成し、日本語と英語それぞれのページを用意しました。

## GitHub Copilot にほぼすべての作業を手伝ってもらった

今回の移行では、GitHub Copilot にコードを書いてもらうだけでなく、移行先のプラットフォーム選定や移行計画の策定から相談しました。その後の Hexo やテーマのカスタマイズ、記事の移行、英語版の作成まで、ほぼすべてを Copilot と一緒に進めました。

むしろ、私自身が直接行った作業のほうが少なかったと思います。主に行ったのは、コードや記事などの成果物のレビュー、GitHub 上で必要な設定、DNS レコードの変更です。

Copilot が作成したものをそのまま公開したわけではありません。特に記事については、移行が正しくできているか、日本語と英語の両方を読み直しました。すべての記事を確認するのは大変でしたが、自分のブログとして公開する以上、内容を確認することは大切だと考えています。

## 親セッションと子セッションで記事移行を並列に進めた

記事の移行では、1 つの親セッションに進捗管理用の CSV ファイルを管理してもらい、記事ごとの移行作業はそれぞれ専属の子セッションに任せました。子セッションには、日本語記事の移行と英語版の作成を依頼し、複数の記事を並列に進めました。

子セッションには、移行が終わったら必ずプレビューを確認するか私に聞くこと、勝手に親セッションに完了を報告しないこともお願いしました。これにより、記事ごとの作業を分けながら、私が内容を確認する機会を設けました。

指示が毎回同じように親セッションから子セッションへ伝わるとは限らず、作業にばらつきが出ることもありました。そのため、子セッションを作成するときのプロンプトは、毎回詳細に指示するようにしました。基本的には移行対象の記事 ID を変えて、同じプロンプトをコピーして貼り付けるだけです。

## 古い情報への注釈も追加してくれた

記事の移行で特に驚いたのは、Copilot が記事の内容が古くなっていないかを調べ、必要に応じて注釈を追加してくれたことです。

当初は、記事の本文をそのまま移行できればよいと思っていました。しかし、例えば Exchange Web Services (EWS) に関する記事では、Exchange Online の EWS の廃止が進んでいることまで調べ、読者向けの注釈を追加してくれました。[テナントに登録されている EWS アプリを探す](../../ja/find-ews-applications-in-tenant/)もその一例です。

過去の記事を記録として残しつつ、現在の状況も読者に伝えられるようになったのは、うれしい発見でした。今回追加された情報を手がかりに、今後は記事の内容自体も最新化していきたいと思っています。

## 移行を終えて

移行後は、ページの表示速度が圧倒的に改善しました。GitHub Pages を使うことで、ブログのホスティングにかかる費用も抑えられます。また、これからは記事を Markdown のテキスト ファイルとして書けるので、運用も楽になるのではないかと期待しています。

今回、Copilot の提案が大きく間違っていると感じることは、基本的にはありませんでした。それでも、記事を日英両方で読み直すなど、最後に人が確認する作業は欠かせませんでした。

移行先の検討から公開まで、これだけ多くの作業を Copilot と一緒に進められたことは印象的でした。しばらく新しい記事を書いていませんでしたが、ブログの移行をきっかけに、また少しずつ記事を書いていこうと思います。
